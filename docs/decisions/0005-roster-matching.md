# 0005. Roster matching for player names

## Status

Accepted

## Context

GPT で読み取ると、打席結果に比べて選手名の誤読が目立った。ユーザーの要望：初回アップロード時に名簿（DB）と照合し、あればそれを採用、なければ担当者に登録してもらう（「打順4の名前」「交代があれば打順4の2人目」）。

## Decision

- 名簿を D1 の `players` テーブル（id, name, created_at）に保存する。1チーム分だけで、チームの区別は持たない。
- 抽出時に名簿の名前を AI に候補として渡し、登録済みの表記で返すよう指示する。
- 抽出後、サーバー側で名前を正規化（NFKC、空白除去、小文字化）して完全一致で照合する。一致すれば `Batter.playerId` を付け、名簿の表記を採用する。あいまい一致はしない（別人に誤って紐付けると、確認で見逃されるため）。
- 一致しない打者は `field: 'name'` の要確認にする。担当者が名前を入力すると名簿に登録し、紐付ける。
- 途中交代は、同じ `battingOrder` の別の打者として出場順に並べる（`slot` = 何人目か）。
- D1 binding は `database_id` を省略し、`wrangler deploy` の自動作成に任せる。テーブルはコードで `CREATE TABLE IF NOT EXISTS` を実行して作る（マイグレーション手順を増やさない）。

## Consequences

- 最初の1試合は全員分の名前入力が必要になる。2試合目以降は、名簿と一致した名前の入力が不要になる。
- 名簿の名前の修正・削除の手段はまだない。
- デプロイ時に D1 を自動作成できない場合（ビルド用トークンの権限不足など）は、D1 を手動で作成し、`database_id` を指定する必要がある。
